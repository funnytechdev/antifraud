# Antifraud

Антифрод-сервис, который в реальном времени проверяет карточные операции: по каждой транзакции
из Kafka выносит решение `ALLOW`, `REVIEW` или `BLOCK` и сохраняет его вместе с причинами.

Реальных данных нет, поэтому в проект входит генератор: он создаёт поток обычных покупок и
подмешивает размеченные мошеннические сценарии. Разметка позволяет измерить качество — сколько
мошенничества поймано и сколько честных клиентов задето зря.

> Проект в разработке. Готов этап 1: рабочий каркас от генератора до решения в базе.

## Архитектура

```
[transaction-generator] ──► Kafka: transactions ──► [antifraud-service] ──► Kafka: decisions
          │                                            │        │
          └──► Kafka: transaction-labels             Redis   PostgreSQL
               (разметка для оценки качества)   (состояние   (решения
                                                   карт,       и их причины)
                                                 чёрные списки)
```

| Модуль | Назначение |
|---|---|
| `contracts` | Форматы сообщений Kafka, общие для генератора и сервиса |
| `transaction-generator` | Модель клиентов, карт и магазинов; поток операций с мошенническими сценариями |
| `antifraud-service` | Правила, скоринг, запись решений, REST API |

## Запуск

Нужны Docker и любая JDK 17+ для запуска Gradle. Проект собирается на JDK 25: если её нет,
Gradle скачает её сам.

```bash
docker compose up -d --wait                  # Kafka (KRaft), Redis, PostgreSQL
./gradlew :antifraud-service:bootRun         # сервис на http://localhost:8080
./gradlew :transaction-generator:bootRun     # поток транзакций, 20 операций в секунду
```

Посмотреть решения:

```bash
curl "http://localhost:8080/api/v1/decisions?verdict=BLOCK&limit=5"
curl "http://localhost:8080/api/v1/decisions/{transactionId}"
```

Сервис можно запустить и без Docker Compose — он сам поднимет зависимости в Testcontainers:

```bash
./gradlew :antifraud-service:bootTestRun
```

PostgreSQL из Compose опубликован на порту 5433, чтобы не конфликтовать с локально установленным.
Порты меняются переменными окружения `POSTGRES_PORT`, `REDIS_PORT`, `KAFKA_PORT`.

## Тесты

Интеграционные тесты поднимают настоящие Kafka, Redis и PostgreSQL в Testcontainers, поэтому

## Правила

Каждое сработавшее правило добавляет баллы риска. Сумма сравнивается с порогами:
от 40 — `REVIEW`, от 80 — `BLOCK`.

| Правило | Что ловит | Баллы | Как устроено |
|---|---|---|---|
| `VELOCITY` | 10 покупок по карте за 2 минуты | 50 | Скользящее окно в Redis на sorted set, один Lua-скрипт |
| `BLACKLISTED_CARD` | Скомпрометированная карта | 100 | Redis set |
| `BLACKLISTED_MERCHANT` | Подозрительный магазин | 60 | Redis set |

Параметры правил и пороги — в `antifraud-service/src/main/resources/application.properties`.

## REST API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/decisions/{transactionId}` | Решение по операции со списком сработавших правил |
| `GET` | `/api/v1/decisions?cardId=&verdict=&limit=` | Последние решения с фильтрами |
| `GET` | `/api/v1/blacklist/{cards\|merchants}` | Содержимое чёрного списка |
| `POST` | `/api/v1/blacklist/{cards\|merchants}` | Добавить значения: `{"values": ["card-0000001"]}` |
| `DELETE` | `/api/v1/blacklist/{cards\|merchants}/{value}` | Убрать значение из списка |

## Инженерные решения

- **Порядок событий.** Транзакции партиционируются по идентификатору карты, поэтому события одной
  карты обрабатывает один поток потребителя строго по очереди.
- **Повторная доставка.** Kafka доставляет сообщения «хотя бы один раз», поэтому каждый шаг
  обработки безопасно повторять: в окне частоты элементом множества служит `transactionId`,
  вставка решения идёт с `ON CONFLICT DO NOTHING`, а решение публикуется с тем же ключом.
- **Атомарность в Redis.** Окно частоты обновляется и подсчитывается одним Lua-скриптом — это одно
  атомарное обращение вместо четырёх команд.
- **Время события, а не время обработки.** Окно отсчитывается от момента покупки. Если сервис
  отстал и разбирает накопившуюся очередь, результат правил не меняется.
- **Объяснимость.** Решение хранит список сработавших правил с баллами и текстом причины.
- **Разметка отдельно от транзакций.** Признак мошенничества идёт в отдельный топик: сервис его не
  видит, как и настоящий банк узнаёт о мошенничестве позже, из претензий клиентов.
